# Break Timer

用于 Ubuntu 26.04 / GNOME Shell 50 的强制休息扩展。已在本机 GNOME Shell 50.1 上使用隔离的 Wayland 会话验证。运行时不需要 Node.js、后台服务或 root 权限。

## 安装与启用

在项目目录执行：

```bash
bash scripts/install.sh
```

首次安装后，注销并重新登录，再启用：

```bash
gnome-extensions enable break-timer@local
gnome-extensions prefs break-timer@local
```

启用后立即遵循当前封禁时段。例如 18:00–19:00 启用会直接显示封禁界面。安装脚本只安装，不会自动启用或改变系统锁屏设置。

也可以安装已生成的压缩包：

```bash
gnome-extensions install --force dist/break-timer@local.shell-extension.zip
```

更新扩展代码后，需要注销并重新登录，才能可靠地载入新代码；Wayland 下不要通过杀死 GNOME Shell 来刷新。

## 默认行为

| 项目 | 默认值 |
| --- | --- |
| 工作周期 | 50 分钟 |
| 休息周期 | 10 分钟 |
| 每日封禁 | 00:00–08:00、12:00–13:00、18:00–19:00 |
| 休息前提醒 | 最后 60 秒顶栏倒计时闪烁 |
| 封禁前提醒 | 最后 180 秒右上角倒计时浮窗，包括全屏应用场景 |
| 空闲抑制 | 默认关闭，遵循系统自动关屏、锁屏和休眠设置 |

初次启用从工作开始；当前处于封禁时段时直接封禁。重新启用会恢复保存的状态。

正常工作时，顶栏仅显示沙漏图标和“工作”，优先排列在右侧状态区的最左边，点击菜单可查看剩余时间。新图标加入时尝试排序一次，不会持续抢占被其他扩展固定的位置。进入休息前的提醒阶段（默认最后 60 秒），顶栏显示并闪烁工作倒计时。

沙漏图标直接使用原项目的 [sand-clock.png](https://github.com/yusanshi/break-timer/blob/linux-deprecated/image/sand-clock.png)，随扩展打包并保留原图颜色和透明度。

工作结束后，在所有显示器上显示全屏遮罩，接管输入。休息结束后仍保留遮罩，直到点击“结束休息，开始工作”，此时开始完整的新工作周期。可以使用 Tab 聚焦按钮，再用 Enter 或空格激活；Esc 不会关闭遮罩。

封禁会中断工作，结束后同样等待用户点击按钮。封禁与正在进行的休息重叠时，两者都结束后才能解除。例如休息至 12:10、封禁至 13:00，则最早 13:00 可解除。即使等到下一个封禁开始才点击按钮，也会重新检查并拒绝解除。

封禁区间的开始时刻包含在内，结束时刻不包含。支持跨午夜（`22:00-08:00`），相邻或重叠区间会合并；`00:00-24:00` 表示全天封禁。设置窗口中清空时段可关闭每日封禁。每日时段修改立即生效，工作与休息时长修改对下一轮生效。

## 锁屏、休眠和计时

| 情况 | 行为 |
| --- | --- |
| 工作时锁屏或休眠，不满一个休息周期 | 暂停工作计时，回来继续剩余时间 |
| 工作时连续锁屏或休眠，达到一个休息周期 | 视为完成休息，回来后等待手动开始新工作周期 |
| 休息时锁屏或休眠 | 休息继续计时，回来重新检查休息和封禁 |
| 遮罩内按 Super+L 或点击“锁定账户” | 交由 GNOME 执行账户锁屏 |
| 系统锁屏后返回 | 系统先按原有设置认证，再恢复休息遮罩或工作状态 |
| 重启、注销或扩展重新载入 | 恢复保存状态；关机时间可计入休息，封禁按当前本地时间重算 |

扩展不会解除 GNOME 的账户锁屏，也不会修改 `lock-enabled` 或 `suspend-lock-enabled`。密码是否需要输入沿用系统设置；普通休息的解除按钮不要求密码。

设置窗口的“锁屏与休眠”中提供“空闲抑制”开关，默认关闭，修改立即生效。关闭时，休息、封禁及“休息完成”等待继续的全屏界面均遵循系统自动关屏、锁屏和休眠设置；若系统已经锁屏，返回时可能需要输入账户密码。

开启后，遮罩显示且系统尚未锁屏时，临时使用 GNOME 的 IDLE 抑制，阻止自动关屏、锁屏和休眠；主动 Super+L 和显式休眠不受影响。关闭开关、解除遮罩、进入系统锁屏或禁用扩展时会释放抑制。如果会话管理器拒绝抑制，则保留系统原有空闲行为并记录日志。

GNOME 50 在关闭自动锁屏时，通知唤醒可能使屏幕只变暗、不再自动关屏。扩展在全屏休息、封禁或等待继续期间对此做兼容处理：空闲抑制关闭且没有键鼠输入的唤醒，会重新按系统“空白屏幕”的等待时间安排自动关屏（例如 15 分钟，另有系统淡出动画）。实际输入后交回系统原有空闲流程；系统设为永不关屏、启用空闲抑制、恢复工作或禁用扩展时取消该安排。不会模拟键鼠输入、修改系统锁屏设置或直接强制显示器断电。

工作/休息时长使用 Linux `/proc/uptime` 的系统运行时间，包含休眠且不受校时影响；每日封禁使用本地日期时间，并在唤醒、时区或时间变化后重新判断。状态每 30 秒及关键转换时保存，非正常崩溃后的恢复精度约为 30 秒。

## 禁用与故障恢复

```bash
gnome-extensions disable break-timer@local
```

如果需要从 TTY 恢复，可用 Ctrl+Alt+F3 登录同一用户后执行：

```bash
DBUS_SESSION_BUS_ADDRESS="unix:path=/run/user/$(id -u)/bus" \
  gnome-extensions disable break-timer@local
```

卸载：

```bash
gnome-extensions disable break-timer@local
gnome-extensions uninstall break-timer@local
```

查看运行日志：

```bash
journalctl --user -b -o cat | rg 'Break Timer|break-timer'
```

约束范围是当前 GNOME 图形会话。TTY、管理员操作、主动禁用扩展、Shell 崩溃及其他用户会话不属于不可绕过的安全边界。内部计时或界面更新异常会停用扩展并释放输入，避免出现无法结束的遮罩。

## 开发与验证

基础检查使用 Node.js 24、GJS 和 `glib-compile-schemas`：

```bash
bash scripts/check.sh
bash scripts/pack.sh
```

纯逻辑测试覆盖工作/休息循环、短锁屏与长离开、睡眠时间、封禁重叠、午夜、跨年、夏令时、校时、重启恢复及配置修改；另有 GJS 实际运行与 `/proc/uptime` 检查。

GNOME 集成检查需要本机 GNOME Shell 50、Python 的 PyGObject、GTK4/libadwaita、可用的图形渲染设备，以及创建本地 D-Bus 套接字的权限：

```bash
bash tests/shell-smoke.sh
```

集成脚本在 `/tmp` 创建独立 D-Bus、配置目录和两个虚拟显示器，使用测试专用驱动启用隔离会话的调试能力；不会连接当前桌面或系统总线。测试覆盖模态输入、虚拟 Alt+Tab/Super/Esc/Super+L、顶栏与浮窗、锁屏模式交接、休眠信号、配置窗口、状态恢复、禁用清理及内部错误恢复。截图与日志保留在脚本输出的临时目录。

通知唤醒后的自动关屏另有约 5 分钟的回归测试，还需要本机 `gnome-session-service`、`gsd-power`、GNOME 的屏保/通知代理、`notify-send` 和 `dbus-monitor`：

```bash
bash tests/idle-notification.sh
```

该测试在隔离会话运行真实的 GNOME 空闲与电源服务，仅模拟登录和硬件服务。系统空闲时间缩短为 20 秒，通过 Mutter 的 `PowerSaveMode` 和电源日志验证通知后再次关屏、输入后恢复原有空闲流程、封禁结束不唤醒、永不关屏、空闲抑制及禁用清理。未启用扩展的对照也会运行；时间线和日志保留在临时目录。虚拟显示器的关屏状态不能替代物理显示器验收。

仍需在真实桌面手工验收：账户密码认证、实际休眠/合盖后唤醒、触控板多指手势、物理显示器热插拔与不同缩放比例。测试中的锁屏交接和休眠信号是模拟的，不会真的锁定或休眠当前电脑。

实现分为 `lib/engine.js`（状态机）、`lib/schedule.js`（每日时段）、`ui/shield.js`（遮罩）、`ui/indicator.js`（顶栏和浮窗）、`extension.js`（GNOME 生命周期）和 `prefs.js`（设置窗口）。
